# EquityLens 投資組合產品規格

> 文件用途：本文件將 EquityLens 的投資組合產品方向轉為可執行的規格與開發對照。它補充根目錄 `ROADMAP.md` 的 V1–V4 路線圖，不取代既有 Roadmap，也不是 API 合約或使用者操作手冊。
>
> 狀態基準：2026-07-11。標示為「進行中」的項目可能位於未提交的工作樹，不能視為正式完成。

## 1. 產品定位與核心流程

EquityLens 不只是記錄持股的表格，而是將持倉、風險、標的研究、ETF 變動與文件資訊連結起來的個人投資分析系統。核心流程如下：

```text
建立資產資料 → 建立交易與持倉 → 觀察組合 → 評估風險 → 研究標的 → 做出決策 → 持續追蹤
```

產品應優先回答下列問題：

1. 我目前持有什麼、成本與市值是多少？
2. 報酬是否值得承擔目前的風險？
3. 風險來自哪些持股、產業或資料問題？
4. 特定標的及事件會如何影響我的組合？
5. 有哪些異常或後續動作值得注意？

## 2. 頁面與資訊架構

### Dashboard｜投資總覽

Dashboard 的責任是快速說明「我的組合現在怎麼了」。應提供總市值、投入成本、現金、未實現／已實現損益、今日損益、累積報酬與資料更新狀態；並呈現決策級風險摘要（例如 VaR、ES、波動率、最大回撤、集中度）及異常提醒。完整模型設定與分析細節應留在 Risk，不應把每種模型做成頂層導航。

### Portfolio｜投資組合與交易帳

Portfolio 是投資事實來源。交易紀錄應是持倉、成本、已實現損益與現金餘額的可追溯來源，而非直接手動修改持股數量。

Portfolio Detail 應涵蓋：

- 組合摘要：市值、成本、現金、未實現／已實現／今日損益與總報酬。
- 持倉：代碼、名稱、數量、平均成本、現價、市值、權重、未實現損益、資料時間。
- 交易帳：買入、賣出、股息、入金、出金、費用及可追溯的日期、數量、價格與備註。
- 績效：組合淨值、累積報酬、基準、超額報酬、最大回撤、TWR 與 XIRR。
- 配置：持股、產業、幣別與資產類別曝險；先以資料正確性為先，再擴充視覺化與比較功能。

### Risk｜風險中心


Risk 應以可行動的風險解讀為目的，而非單純展示數學模型。

- 風險摘要：波動率、VaR、ES、最大回撤、集中度與模型資料狀態。
- VaR／ES：顯示信賴水準、持有期間、回溯區間、資料更新時間與計算失敗原因。
- 風險貢獻：後續提供單一持股、產業及幣別的 component／marginal／incremental risk，讓使用者知道風險來源。
- 回測：後續提供 breach 次數及模型預測與實際損益的比較。

風險模型屬於分析方法，不應取代使用者任務成為主要導航。資料不足時必須說明原因，不以示範曲線或假資料補足。

### Research｜標的研究

Research 應同時回答「這是什麼標的」及「它對我的組合有何影響」。標的詳情後續應包含基本資料、價格與歷史表現、基本面、報酬／風險指標，以及該標的在使用者組合中的持股、成本、市值、權重、損益及風險貢獻。

## 4. 投資帳與績效計算規則

第一版範圍固定為台股、TWD、現金股利；不含股票股利、拆股、減資或跨幣別換匯。

| 項目 | 規則 |
| --- | --- |
| 持倉與成本 | 由交易彙總；平均成本可作持倉摘要，但不是已實現損益依據。 |
| 已實現損益 | 賣出交易以 FIFO 配對買入 lot，納入買賣手續費。 |
| 股息 | 依除息日前持股建立待確認項目；發放日才成為可用現金及績效內部報酬，不自動再投資。 |
| 今日損益 | 今日總資產 − 前一交易日總資產 − 今日外部淨入金／出金；包含價格變動、已實現損益、已入帳股息與費用。 |
| 基準 | 固定使用台股加權含息總報酬指數，與組合使用相同起始日正規化比較。 |
| TWR | 依每日淨值及外部入金／出金切割子期間；股息保留在組合現金，屬內部報酬。 |
| XIRR | 使用外部入金／出金及期末總資產現金流，輸出年化實際報酬。 |

## 5. 開發優先順序

### 階段一：完成可追溯的投資帳

1. 完成股息待確認清單、確認／調整／略過流程與交易紀錄分頁。
2. 以 FIFO 實作已實現損益、賣出成本配對與可追溯明細。
3. 納入現金餘額、外部入金／出金、未實現／已實現／今日損益。
4. 驗證交易新增、刪除、持倉歸零與股息入帳後的重算正確性。

### 階段二：完成可信且可解釋的風險與績效

1. 匯入台股加權含息總報酬指數，建立組合與基準的每日序列。
2. 實作 TWR、XIRR、累積／超額報酬、最大回撤與期間切換。
3. 顯示 VaR／ES、EWMA 等模型的設定、資料期間與資料不足原因。
4. 增加持股／產業／幣別風險貢獻，再規劃回測能力。

### 階段三：擴充投資情報與營運能力

1. 建立 ETF Snapshot、持股變化與風格分析。
2. 完成文件庫、可引用的 AI 分析與 Portfolio-aware research。
3. 建置 Alerts 與 Data Health，將資料延遲、缺值與重要事件轉為可行動提醒。

## 6. 完成判準

- 文件中的「已完成」項目必須能由現有路由、Controller 或服務追溯。
- 「進行中」項目必須明確標註為尚未提交或尚待驗證，避免與正式發佈功能混淆。
- 不以假資料掩蓋資料不足；所有績效與風險曲線均需說明可計算範圍及不足原因。
