# 多輪評估器 v2

適用於 `conversation_journey_v1`。修改的是評分方法，既有題目、原始回答、行情 fixture 及單輪 `research_v1` 考卷維持原樣。新分數不能直接與 v1 的總通過率比較，也不能當成產品改善的證據。

## 三種結果分開報告

1. `checks` / `independent_check_counts`：依原始輸出、持久化事件、資源 ID、公開報告核實資料與獨立數學計算判定。只有這些檢查決定 `status`。
2. `product_gates` / `product_gate_counts`：產品自己的 Quality Gate 是否接受／拒絕／未記錄，包含研究及投組 Run。這是產品行為觀測，不是獨立正確性標籤；拒絕仍完整保留原因與證據位置。
3. `review_queue.json`：語義、證據歧義和閘門誤擋／漏擋的覆核清單。預設 `unreviewed`、`verdict: null`，不可當成已通過。

因此，產品拒絕的答案仍可能在獨立檢查中數值正確；產品接受也可能缺答或算錯。若語義尚未覆核，獨立檢查全綠仍不足以證明整段成功。11 組案例繼續保持 draft，不提供完整對話成功率。

## 財報檢查

規則位於 `evals/cases/conversation_research_rubric_v2.json`，只處理這組題目核實過的三個研究 reference。規則綁定原研究考卷 hash；考卷變更後須重新核實，不能沿用舊規則。可接受頁面、文件 ID、標題、PDF SHA256、引用必要內容及核實方式均記錄於規則中。

- **事實完整性與正確性**：核對公司／股票代碼、年度、指標、單位和數值。標題可提供公司／年度，未明示時承接題目；明確寫另一公司、年度、季度不算回答原問題。基本與稀釋 EPS、產品線占比與年增率分開解析。
- **矛盾**：同一公司、年度和指標同時出現正確與錯誤值，仍失敗。不能靠把標準數字放在別處通過。
- **缺答與缺紀錄分開**：有完整答案但不回答必要指標、回答資料不足、或空答，判必要事實失敗；沒有取得答案紀錄才無法驗證。有正確數字但語法無法可靠綁定指標，送覆核而不直接通過。
- **引用支持**：數值主張必須連到段落／指標範圍或表格儲存格的有效引用；引用應命中經核實頁面，且摘錄具有該指標或計算運算元。只有頁碼／引用編號正確不夠。缺少摘錄屬證據未捕獲；摘錄明顯無關或引用錯置屬失敗。
- **子項保留**：每個指標的 `research_fact`、`research_source_support` 及引用完整性存在 `subchecks`。聚合順序為「已知失敗優先，其次未知，最後才通過」；一項未知不能掩蓋另一項已知失敗。子項不重複計入頂層檢查分母。

原件核實增加台積電 2025 合併財報第 10 頁作為基本 EPS 的替代來源，原第 58 頁仍有效；沒有把所有頁碼容差調大。第 10 頁是掃描頁，已渲染檢查 114 年度及基本／稀釋每股盈餘列，核實方式明記為 agent visual review，非人工校準。

多輪使用者沒有要求毛利率小數位，因此明確標註「財報表列整數 60%」可接受；若聲稱按金額精算卻得到 60.0%，仍失敗。單輪原題要求計算至小數一位，其原來的 59.9% 標準不變。

### 自動辨識的界線

這是有限的中文段落與 Markdown 表格辨識器，不是完整語義理解器。常見公司名稱、年份、前一年、指標前置標籤和表格欄位有反例測試；新的公司別名、複雜指代、跨段落表格、否定／假設句、引用中的語義蘊含仍需覆核。引用內容的關鍵詞／運算元檢查也不能替代逐句來源閱讀。不得把 `research_grounded` 通過解釋為整份答案所有額外主張都正確。

## 人工覆核與 LLM 裁判校準準則

每筆覆核應包含：`reviewer`、`verdict`（pass / fail / unverifiable）、`rationale`、支持判定的原文與工具／來源位置。`response_sha256` 綁定完整案例的 canonical JSON；修改答案後必須重新標註。人工結果先保留在獨立檔案，不直接改寫原始回答或程式檢查結果；目前 CLI 不會匯入人工裁決或啟動語義 judge。

| 語義項目 | 通過條件 | 失敗例子 |
|---|---|---|
| 目標承接 | 回答當前問題，保留已確認參數，正確處理公司／投組切換及 reset | 只記得投組 ID，卻忘記使用者正在要求減碼方案 |
| 研究到曝險 | 引用前輪已核實事實並結合本輪持倉；前輪失敗則明示缺口 | 把財報拒答的內容寫成已核實結論 |
| 推論與不確定性 | 區分事實、歷史數學、條件式影響、未知 ETF 穿透 | 把財報改善說成保證股價上漲，或捏造 ETF 成分權重 |
| 方案取捨 | 同一期間、價格基礎和方法比較，說明現金、曝險和風險代價 | 把兩種風險方法的數字放在同一前後比較表 |
| 資料不足 | 說明缺什麼及其影響，仍回答可支持的部分 | 只有 60 筆報酬卻聲稱已完成需要 120 筆的估計 |
| 額外主張 | 每個實質數字和因果說法能對應來源；沒有相互矛盾 | 關鍵答案正確，但額外加入算錯的年增率 |

校準流程：

1. 從成功、失敗、拒答、資料不足、公司／投組切換及 reset 中分層抽樣。人工先看原文與來源，不先看模型裁判判定，避免受其影響。
2. 至少兩名人工評審獨立標註，再裁決分歧；缺證據保留 unverifiable，不要求猜測。覆核清單中的 agent 抽查不能冒充這個人工標準集。
3. 將標準集分為調整用與保留驗證集。固定 rubric、judge 模型、提示版本，包含錯公司／年度、錯數字、引用錯置、漏答和混用基準反例。
4. 啟用前至少取得 30 個保留驗證判定，pass/fail agreement ≥ 90%、Cohen's kappa ≥ 0.8；所有列入驗證的越權、持倉變更及重大數值／因果錯誤反例不得被誤判通過。另報 unknown 比例，不得刪掉 unknown 後宣稱高成功率。這些是校準門檻，不是目前已達成的結果。
5. 未取得人工標準集或未過門檻，語義結果維持 unverifiable。即使通過校準，仍保留人工抽查與分項誤判統計；安全與數學硬檢查不能由 judge 覆寫。

## 重評與重現

```bash
PYTHONPATH=evals python -m equitylens_eval.conversation rescore \
  --responses exports/benchmark/<run>/results/responses.jsonl \
  --out exports/benchmark/<new-score-directory>
```

v1 舊資料沒有評分規則快照，首次重評使用目前 v2 規則；v2 重評預設沿用來源資料夾的 `scoring_rubric.json` 並驗證 hash。要明確換規則，使用 `--rubric <path>`，另建輸出目錄。`score_meta.json` 保存評分器版本、source hash、rubric hash 及原結果位置；原本 `run_meta.json`、題目、研究標準、fixture 和回答保持不變。

完整驗證：`PYTHONPATH=evals python -m pytest evals/tests`。這些測試與離線重評不呼叫 LLM、不接觸正式資料庫。
