# 台積電、鴻海年報重新索引後的 eval（2026-11-02）

同日正式基準（[2026-11-02](../2026-11-02/README.md)）為 6/11。追查失敗題後發現年報抽取管線只把約 3 成頁面放進索引；修正 2330、2317 兩家 2023–2025 年報的索引後重跑，**通過率 6/11 → 7/11（54.5% → 63.6%）**，幻覺率維持 0。

## 發現的問題

以 `scripts/AnnualReportExtractor` 相同邏輯逐頁重放兩份 2025 年報：

| 頁面 | 內容 | 被丟棄的原因 |
|---|---|---|
| 2330 p.9 | 合併綜合損益表 | 影像頁，PdfPig 文字層為 0 字，`PassesQualityGate` 丟棄 |
| 2330 p.58 | 每股盈餘附註 | 分類器判為 `Review`（未分類），Review 頁整頁丟棄 |
| 2317 p.112 | 產品別收入 | 同上，`Review` 整頁丟棄 |

| 文件（3 年合計） | 原索引頁數 | 有內容頁數 | 未索引比例 |
|---|---|---|---|
| 2330 台積電 | 83 | 270 | 約 69% |
| 2317 鴻海 | 131 | 508 | 約 74% |

台積電財報 p.1–14（查核報告與四大報表）為掃描影像，原本完全不在索引中。60 頁上限在這兩家不是主因。

## 修正方式（僅限 2330、2317 六份年報）

1. **重新抽取**：與原抽取器相同，但 `Review` 頁改為保留（未分類者標為「財報附註」），並取消每份 60 頁上限。
2. **影像頁轉錄**：PdfPig 抽不到文字的 44 頁，以 170 DPI 轉成 PNG，用 Codex（`gpt-6.1-sol`）逐頁轉錄為 Markdown 表格。prompt 要求逐字抄錄、不得計算或四捨五入、看不清楚標 `[無法辨識]`。
3. **轉錄驗證**：
   - 數字欄位 `[無法辨識]`：0 處（僅出現在被印章遮住的標題）
   - 損益表勾稽（營收−成本=毛利、…、稅前−所得稅=淨利）：2023/2024/2025 各 8/8
   - 資產負債表「資產＝負債＋權益」：三年皆平衡
   - 跨年一致：2024 年報前期欄與 2023 年報本期數字完全相同（兩次獨立轉錄）
4. **寫入**：單一交易刪除六份文件舊 chunk（214 筆，embedding 連帶刪除）並寫入 778 筆新 chunk；`--embed-chunks` 以 `text-embedding-3-small` 產生 778 筆 embedding，0 失敗。舊 chunk 與 embedding 已另行備份。

抽取規則修改目前只用於這次重建，`scripts/AnnualReportExtractor` 尚未改動；其他公司仍為舊索引。

## 下一步

剩餘數字題的失敗已從「資料未索引」轉為檢索後段問題：

- **排序與 context 預算**：EPS、聯發科營收的正確頁有撈到但未被採用，需檢查 rerank 與最終證據選取。
- **來源規劃**：年度數字題應優先年報，而不是最新一期法說會。
- 將抽取規則修正（保留 Review 頁、影像頁轉錄、勾稽驗證）正式寫回抽取管線，套用到其他公司。
